# 代码评估规则

此文件由用户维护。每次点击“开始代码评估”时重新读取，无需重启服务。
规则用于对本次自动分析证据进行 AI 评审；只有完全缺少相关源码、补丁或 PFS 证据时才标记“待确认”。
评审需要可用的 Codex 配置。调用失败时页面明确提示，原有自动分析结果仍然保留。

## 自定义代码评估规则

### 总原则

以当前代码基线为本地代码，以 Gerrit topic 的改动为对比对象，并结合本次 PFS 判断 topic 合入后的实际差异。AI 必须根据已有 topic、本地代码和 PFS 证据直接给出明确判断；只有完全没有可核对证据时才允许使用“待确认”。不要因为存在一般性不确定性、没有运行设备或无法编译就默认输出“待确认”。只输出发现的问题、风险和待确认项；没有问题的检查项不输出。相同问题合并，禁止重复描述。

### 1. PFS 覆盖情况

逐项核对 PFS 与 topic / 本地代码，找出未实现、实现不完整或实现不一致的需求。只有完全没有相关代码或 PFS 证据时才列为“待确认”。输出 PFS 要求、相关代码位置、差异和影响。

### 2. 屏幕与标题适配

只检查 `480×480` 和 `390×450`。由 AI 对照 topic 与本地代码，核查圆屏 gapp 与方屏 gapp 是否一一对应、是否映射到正确的 application / Screen / style，以及 topic 是否遗漏了对应屏幕的修改、布局、图片资源引用或资源注册。重点检查方屏页面标题是否与需求一致、语义正确、显示合理。没有独立文件但已有明确复用依据时不视为问题。

### 3. 表冠、按键与触摸

对照 PFS 和项目现有交互规范，检查 topic 新增或修改的表冠、按键、触摸、返回事件及其生命周期。只报告缺失、未注册、无法触发、方向或行为错误、重复响应、退出后未清理，以及 topic 与本地实现不一致的问题。

### 4. `uiframework` 依赖

列出 topic 新增或修改、但当前本地代码不存在、不兼容或当前配置不可用的 `uiframework` 函数、类型、宏和回调。输出接口名称、topic 使用位置、预期头文件或模块、差异和影响；本地已有且兼容的接口不输出。

### 5. 合入风险

只评估由 topic 与本地代码差异直接引起的风险，包括编译链接、依赖、屏幕显示、资源、表冠 / 按键 / 触摸、运行时、内存存储和已有功能回归。每项用“等级｜位置｜问题｜影响｜建议验证”格式输出。能从 topic、本地代码或 PFS 判断的内容必须直接判断为有问题或无问题；只有完全缺少相关代码、PFS 或差异证据时才标记“待确认”，不要把推测写成事实。

### 输出格式

问题存在时按以下格式逐条输出：

`[高/中/低/待确认] 分类｜位置｜问题｜影响｜建议`

没有任何问题、风险或待确认项时，只返回 `NO_ISSUES`。禁止输出“无问题”“未发现风险”“全部通过”等正常结论。
