# 代码评估规则

此文件由用户维护。每次点击“开始代码评估”时重新读取，无需重启服务。
规则用于对本次自动分析证据进行补充评审；缺少源码、补丁或运行证据时，必须标记“待确认”，不能推断为通过。
评审需要可用的 Codex 配置。调用失败时页面明确提示，原有自动分析结果仍然保留。

## 评估要求

1. 以用户选定的本地代码基线为准，只评估本次功能或 Gerrit topic 的移植影响。
2. 区分本地已有接口与真正缺失的依赖，不将已有接口重复计入工作量。
3. 检查涉及的硬件能力是否有配置证据支持；没有证据时列出待确认项。
4. 存储余量必须注明依据；没有 map 文件时不能判定空间充足。
5. 工期应说明依据、额外依赖和不确定性，不把估算当成承诺。
6. 补丁读取失败、分析降级或证据不完整时，明确说明对结论的影响。

## 自定义规则

### 输出要求

只输出发现的问题、具体风险和影响结论的待确认项；不输出通过项、正常项、检查过程、规则复述或总结。相同问题合并，每项简要说明位置、问题、影响及处理建议。下文的检查范围用于内部评审，不要求逐项展示正常结果。没有问题、风险或待确认项时，只返回 `NO_ISSUES`，页面不显示自定义规则评审区域。禁止输出“无问题”“未发现风险”“全部通过”等正常结论。评审失败仍需显示失败提示，不能视为没有问题。

### 1. 方屏 / 圆屏适配与图片资源完整性

检查本次 topic 涉及的界面、布局、样式及图片引用，确认方屏与圆屏是否均已完成必要适配，重点识别仅修改方屏而遗漏圆屏的情况。结合目标项目的屏幕形态、分辨率、条件编译和资源组织方式，检查两种屏幕所需的图片资源、资源注册及引用路径是否完整、匹配且可用；允许有依据的资源复用，不要求无差别复制资源。

逐项列出受影响的页面或模块、方屏 / 圆屏对应文件或资源路径、发现的遗漏及影响。区分“已确认缺失”“无需独立适配”和“待确认”；缺少对应源码、资源目录或引用证据时，不得判定适配完成或资源齐全。

### 2. uiframework 接口依赖与本地缺口

检查本次 topic 的修改是否新增或改变了对 `uiframework` 的接口依赖，包括函数、类型、宏和回调约定。以用户选定的当前项目代码基线为准，核对相关接口的声明、实现、签名及条件编译可用性，区分“本地不存在”“签名或行为不兼容”和“存在但当前配置不可用”。

列出当前项目缺失或不兼容的 `uiframework` 接口，注明接口名称、topic 中的调用位置、预期所属头文件或模块、本地核对依据、影响及建议补齐的依赖。不要将本地已有且兼容的接口列入缺失清单；无法确认接口归属或缺少核对证据时，单独列为待确认项。

### 3. Topic 合入风险评估

评估将本次 topic 合入当前代码基线后可能引入的风险，覆盖编译与链接、依赖兼容、方屏 / 圆屏显示及资源加载、运行时异常、内存与存储占用、事件处理及生命周期、已有功能回归等方面；仅报告与本次改动有明确关联的风险，避免泛泛罗列。

每项风险应说明风险等级（高 / 中 / 低）、相关 change 或文件位置、判断依据、触发条件、影响范围、建议处理措施及验证方法。区分已确认问题与潜在风险；缺少证据时标记待确认，不得将推测写成已发生的问题。最后汇总合入前应解决的阻断项，以及可通过后续验证确认的事项；证据不足时不得直接给出“可以安全合入”的结论。

### 4. 新增 Screen 的输入事件完整性

当本次 topic 新增或引入 Screen 时，检查该 Screen 涉及的按键、旋钮、触摸及返回事件是否满足项目需求和现有交互规范。核对事件注册、监听生命周期、事件分发、页面进入与退出后的清理，以及方屏 / 圆屏或不同硬件配置下的可用性。

只列出缺失、未注册、无法触发、重复注册、退出后仍响应、与需求不一致或证据不足的事件，并注明 Screen、事件类型、代码位置、影响和建议验证方式。没有新增 Screen 时不输出本项；已有事件完整且无风险时不输出。
