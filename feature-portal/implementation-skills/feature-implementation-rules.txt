# Feature Portal 功能实现规范
#
# 请在下面描述功能实现时必须遵守的规范和原则。
# 每行规则都会作为本次 PFS 功能实现时的约束，供 CodeGraph + Codex 使用。

[实现范围]
- 只实现本次 PFS 明确提出的需求。
- 不做与本次需求无关的重构、格式化或目录调整。
- 优先复用已有模块、接口、组件和页面，不重复建设已有能力。

[代码原则]
- 先使用 CodeGraph 查询模块归属、入口、调用链和影响范围，再修改代码。
- 修改前确认现有代码行为，保持已有功能兼容。
- 新增接口、宏、配置或依赖时，必须确认本地代码是否已经存在。
- 发现本地未定义的宏、接口或依赖，必须在评审结果中明确上报。

[Screen 规范]
- 只有需求明确需要时才新增 Screen。
- 新增 Screen 必须使用项目规范的 importScreen 方式接入 application。
- 同时检查 gapp 注册、配置、资源和页面生命周期。
- 页面进入、退出、返回、重复进入和异常中断后必须能够正确恢复。

[分辨率与布局]
- 方屏、圆屏必须分别确认布局和裁剪效果。
- 390×450 分辨率必须使用对应的布局和 style 规则。
- 不允许直接复制 480 分辨率坐标、尺寸或 style 后不做适配。
- 文字、边距、点击热区、焦点和滚动区域必须适配目标屏幕。

[事件规范]
- 按键：确认、返回、上下左右、短按、长按和重复触发必须明确处理。
- 触摸：点击、抬起、取消、滑动和边界区域必须明确处理。
- 右滑：必须确认与返回手势不冲突，并验证页面恢复状态。
- 旋钮：顺时针、逆时针、按下、长按和焦点切换必须按项目能力处理。
- 事件监听必须在退出页面时清理，禁止重复注册导致一次操作多次响应。

[验证与交付]
- 修改完成后只执行与本次需求相关的最小测试。
- 功能实现阶段禁止执行固件编译、烧录和完整构建；统一由后续“代码编译”步骤执行。
- 输出修改的目录、文件、测试重点、风险和未完成项。
- 未验证的内容必须标记 UNKNOWN，不得默认通过。
