# feature-implementation-rules

## 使用范围
仅用于实现当前 PFS，不得扩展需求范围。

## 实现规范
功能实现规范（仅按本次 PFS 实现，不得发散）
1. 先使用本地 codegraph summary/module/path/file/impact 查询现有模块、入口、调用链和归属，再决定修改位置；优先复用已有能力，不新建平行框架。
2. 只实现 PFS 明确提出的需求；不顺手重构、不改无关模块、不改变已有公共接口行为。
3. 若需要新增 Screen，必须在正确的 application 文件中 importScreen，并同步检查 gapp 注册/配置；根据需求决定是否新增 style。
4. 方屏/圆屏、390×450 目标分辨率、按键、触摸右滑、旋钮事件必须遵循仓库已有规范；不能直接复制 480 坐标或 style。
5. 处理进入、退出、返回、重复进入、异常中断后的界面恢复和事件监听清理，禁止重复注册造成重复响应。
6. 修改完成后只运行与本次改动相关的静态检查或轻量验证；绝不执行固件编译、烧录或完整构建。输出修改目录、关键文件、测试重点和未解决风险。

## 当前 PFS
1、新增进入运动后直接到达Template ReadyGo页面或ReadyGo页面的流程
2、新增HSP连接完成后进入ReadyGo页面的流程
3、新增在HSP连接页面点击跳过后进入ReadyGo页面的流程
4、新增ReadyGo页面点击Go后进入自动校准提示页，并支持开始10秒倒计时校准或退出返回ReadyGo页面
5、新增运动开始后跑步阶段自动校准成功时通过toast和震动提示，自动校准未成功时不提示
6、增加HSP版本号确认逻辑：版本号未确认动态校准支持状态时进入静态校准流程
7、新增静态校准流程中的首次佩戴提示页、校准确认页、校准指导页和佩戴提示页
8、新增跳过校准后的跳过确认页，并支持点击校准进入校准或点击继续跳过进入ReadyGo/Template ReadyGo页面
9、新增校准成功后进入成功确认页，再返回ReadyGo/Template ReadyGo页面
10、新增校准失败后进入失败确认页，再返回校准确认页
11、明确多运动类型共用首次佩戴提示页
12、保持校准成功/失败对运动中及运动记录的对齐逻辑不变
