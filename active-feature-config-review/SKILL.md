# 功能配置审查

以“应支持的功能是否具备完整配置链路”为结论单位，不以宏差异数量代替功能缺陷数。

## 范围与输入

从用户及上下文确定工作区、目标/可选对照项目、平台/型号、分支、负责功能和交付版本。自行读取能唯一定位的信息；同名项目多平台时优先同平台对比，无法消歧再询问。不自行切分支或同步仓库。

默认目录见 [owned-features.yaml](references/owned-features.yaml)。这是组内检索线索，不是永久需求或所有项目的必配清单。用户范围和当前需求优先；按来源核实产品、版本、备注和子功能要求。飞书读取使用环境提供的 lark-doc/lark-base；无访问能力时保留证据缺口，不猜支持范围。

模式可组合：单项目按需求审查；跨项目比较；有构建输出时复核生效值。仅有源配置也可继续，注明未验证构建。

## 开始前提醒与功能清单

开始实质核查前，必须向用户列出本次待检查的功能点。根据用户指定范围和目录生成清单；已明确只检查某些功能时只列这些项，不扩大到默认全部功能。范围未限定时，列出目录中的全部功能名称，并将乳酸阈检测与乳酸阈心率区间分开列出。运动数据项同时说明所查内容，例如乳酸阈的当前/平均/本段/上段百分比，以及匹克球2.0的新旧类型、总/正/反挥拍和发球裁剪。

如果用户及当前上下文均未指定对比项目，必须明确提醒：“尚未指定对比项目，本次先按单项目审查，以适用需求和当前源码为依据，不进行跨项目差异比较；后续可补充对比项目。”不得静默选择oslo或其他历史项目，也不把未提供对比项目作为阻塞条件。提醒和清单给出后，继续已授权的只读检查，无需额外等待确认。用户已提供对比项目时，直接说明目标与对比项目，并列清单，不重复索取。

示例（用户仅关注乳酸阈区间和匹克球2.0，未提供对比项目）：

> 尚未指定对比项目，本次先按单项目审查，依据适用需求和当前源码核查；后续可补充对比项目。
>
> 待检查功能：
> - 乳酸阈心率区间：大小核宏、4个百分比项、区间设置和分段数据。
> - 匹克球2.0：新旧类型、列表迁移、总/正/反挥拍、发球裁剪及展示/保存配置。

## 审查流程

1. 记录相关仓库HEAD、分支、本地修改和输入摘要。defconfig、最终配置、编译头文件分别登记项目身份和核角色，排除旧项目输出。
2. 按功能建立“需求/适用版本 → 宏及资源/协议依赖 → 执行核 → 运动类型/组 → 数据项 → 页面/保存条件”的证据矩阵。
3. 宏和核分工按 [macro-and-core-review.md](references/macro-and-core-review.md) 核查。区分支持宏、本地实现BUILD宏和代理方向；公共结构受宏影响时检查两核契约。主核开启不代表计算所在小核也开启。
4. 数据项按 [sport-data-review.md](references/sport-data-review.md) 核查。每项目独立发现工作表，按标识和组对齐XLSX、CSV、生成头文件；属性相同还需检查类型、列表、迁移可达性。
5. 用当前代码解释差异，分别确认配置支持、有效出值、页面展示、记录保存。需深入算法/跨核/APP链路且可用时，复用 `active-sport-data-e2e-analysis` 的相关参考；没有该技能不妨碍基础审查。
6. 输出本地功能报告和对照附件。非负责范围的问题只作外围备注，不扩大主结论。

## 工具

脚本只提取证据，不判断产品必须支持哪些功能，不修改业务配置、生成代码、构建或刷机。

```bash
# 标签使用 项目.main / 项目.hub，路径按实际平台定位。
python3 <skill-dir>/scripts/compare_configs.py \
  --config atlas.main=/workspace/configs/mhs003s/mhs003s_atlas_defconfig \
  --config atlas.hub=/workspace/configs/mhs003s/mhs003s_atlas_sensorhub_defconfig \
  --config oslo.main=/workspace/configs/mhs003s/mhs003s_oslo_defconfig \
  --config oslo.hub=/workspace/configs/mhs003s/mhs003s_oslo_sensorhub_defconfig \
  --final atlas.main=/workspace/build/.config \
  --header atlas.main=/workspace/build/out/config/autoconf.h \
  --out /workspace/reports/feature-review
python3 <skill-dir>/scripts/compare_sport_items.py \
  --root /workspace --projects atlas oslo --out /workspace/reports/feature-review
```

可传 `--features lthr-zone pickleball-v2` 或自定义 `--catalog`；其余参数见 `--help`。需要PyYAML，数据脚本另需openpyxl；缺包时用隔离Python环境，不修改仓库依赖文件。源格式无法解析时报告或失败，不把缺失解析结果当成false/通过。

## 判定和输出

按功能区分明确缺口、功能差异、布局差异、共同问题、不适用、待确认。对照项目不是正确答案；共同漏配需单列。UNSET、明确n、最终未生成、解析失败分开。需求不清时报告实际状态及“若本版要求支持则需补齐”，不要求跨项目无差别复制。

主报告包含范围/版本/证据层次、功能结论表、问题及源码行号、影响/建议、已验证和缺口。附件包括所选宏、类型、数据项CSV，保留ID/英文标识、来源、XLSX坐标、头文件行号。数量注明是宏/核行、属性数还是组×属性单元数。配置一致不等于功能验收通过。

报告中的结论表、逐功能审查表、宏/核对比表、运动类型表、数据项表和影响表均用图标配合文字标出正确点和问题点，并在报告开头给出统一图例：✅ 配置/属性已确认或按需求正确关闭；❌ 已确认缺口或目标能力未启用；⚠️ 项目差异、风险或适用范围需核实；❓ 证据不足/未验证；➖ 该类型原本不支持该项。同一功能的正确点和缺口分别标注，未启用但需求不明时注明待确认。不能机械地把false/n标❌（如匹克球2.0按需求关闭发球），也不能把两项目一致一律标✅（可能共同漏配）。必要时分列项目和判定，让原值、差异、影响清晰可辨。✅不代表真机验收通过；图标不替代文字证据。CSV/JSON附件保留原始值，避免图标破坏程序处理。

默认只读，不执行完整sport_gen.py；原生成器验证在隔离副本重定向所有输出。本技能不隐含修改配置、构建、发消息、写Jira或发布飞书报告的授权，按具体任务授权执行。
