# 宏、构建与核分工

按项目/平台定位主小核defconfig，boot/recovery/工厂配置不代替业务配置。源配置与最终.config分列；核未编译按用户指定源配置审查，缺少产物不是缺陷，旧产物不参与判定。

从HMI_PRODUCT_CUSTOMIZE_DIR、board宏和构建项目确认产物身份，APP_SENSORHUB区分核角色。mtime不能单独证明同次构建。记录输入hash及仓库HEAD。脚本用标签项目名核对身份，支持 --expect 标签=项目；身份冲突的产物排除，未知身份/核标志保留待核实。

`=y`、明确n、UNSET、解析失败分开。UNSET可能经default/select变成y；查Config.in依赖、默认值、select和最终输出。消失的符号可能未接入或废弃，不能只添加y后宣称修复。

追踪FEATURE宏、BUILD宏、module.mk的源码选择和local/remote代理。主核只有代理时，要检查小核内部的计算宏。GoMore检测SDK与区间百分比可以在不同核，不要求把SDK迁移到小核。

公共头文件中宏改变枚举、字段、结构布局或消息长度时，检查两核契约。类型不同先报风险；没有现场证据不能宣称已经造成错位数值或内存破坏。

每项问题需有适用需求、当前证据、首个缺口、影响与验证边界、建议。两项目相同仍可能共同漏配；训练入口位置不同不等于功能缺失。小核未编译时可确认源配置及条件编译问题，实际设备表现仍待验证。
