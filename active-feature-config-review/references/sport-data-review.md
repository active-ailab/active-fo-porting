# 运动类型与数据项

从当前源码确认sports.xlsx、sport_gen.py、sports.csv、生成头文件关系。每项目在参与生成的code_attr_*中定位产品列，不能按项目名猜表或列。确认生成器仍遵循“组格精确等于Yes、产品格为真值”；脚本按此规则实现，规则改变时先适配，不把非空字符串当业务支持意图。

以属性英文标识/ID和实际运动组对齐；中文描述可能重复，不能用“组+中文名”作唯一键。生成头按分组及属性顺序核对数量和注释，不可解析的格式要报告证据缺口。XLSX公式缓存缺失时查公式，不直接判false。

CSV可能只是导出资料；pandas会把字面值NA识别为空。三种来源冲突应分别报告，以实际编入头文件表示当前属性支持，不能静默择一。完整生成器可能改写多个产品文件，验证需在隔离副本重定向所有输出。

从sport_type_auto.h查ID，从Sports及sport_type_in_<project>.h查支持，从sport_group_auto.c查实际type→group。属性已支持但新类型/默认列表/已有用户迁移没开启时，功能仍不可达。多个运动共享组，不按运动名称猜算法。

四层分别判断：配置支持（类型、映射、属性）、有效出值（执行核、算法输入/模式）、页面展示（编辑过滤、默认页、格式）、记录保存（赋值、has标记、协议和消费者）。可选项不等于默认显示，也不等于落盘。区间编号、百分比、区间用时和分段百分比不是同一份数据。

脚本目录schema：fields选择字段全部组；group_sport_types选择实际映射组全部属性；filtered_group_sport_types配合group_field_prefixes/group_fields选择游泳心率等范围。项目映射缺失、重复产品或格式变化不得静默跳过后报通过。

脚本不能验证默认页、算法出值、APP解析和协议端到端行为；没有证据标待确认。需深入链路时复用运动数据E2E流程，不把本技能扩展为日志诊断或算法测试框架。
